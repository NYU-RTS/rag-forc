- Claude Code searched torch's logging module for StreamHandler and LazyTraceHandler class definitions
- Claude Code explained that `%%capture` only swaps Python-level `sys.stdout`/`sys.stderr` objects, while logging handlers (from transformers, torch, loguru) are bound to stream references once at import time before the capture cell runs, so handlers keep writing to original stderr; recommended three fixes: reconfigure loggers with `setLevel(logging.ERROR)` or `set_verbosity_error()`, use `torch._logging.set_logs()`, or swap file descriptors with `os.dup2` at OS level
